# Synthetic Event fixtures

These are small, non-personal raw SD examples for the contract in
`docs/EVENT_DATA_MODEL.md`. The valid WAVs intentionally contain only eight silent
frames (60 bytes each), so they are structural fixtures rather than realistic
utterance durations.

- `complete`: READY audio, RECOGNIZED plus UNKNOWN, successful COMPLETE.
- `busy`: READY audio and a mappingless BUSY sentinel, COMPLETE_WITH_ERROR.
- `incomplete`: OPEN and a DISCONNECTED sentinel with no audio/complete terminals.

`expected.diagnostic.json` is generated by the existing SD inspector; it retains
CSV strings and is not a separate device API. From the repository root:

```powershell
python tools/inspect_event_sd.py protocol/examples/event_data/complete
python tools/inspect_event_sd.py protocol/examples/event_data/busy
python tools/inspect_event_sd.py protocol/examples/event_data/incomplete
```

Compare the output with the corresponding `expected.diagnostic.json`. The
incomplete fixture remains INCOMPLETE while preserving its known request/count.
